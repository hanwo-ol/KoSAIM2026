> **Executive Summary**  
> IRB 연구계획서 작성은 연구 정보를 구조화하고 문헌을 검토하는 데 시간이 많이 듭니다. 외부 생성형 AI 서비스에 연구 내용을 넣으면 **개인정보와 보안 문제**도 생깁니다. 이 연구는 연구자가 자유롭게 쓴 **한국어 연구 설명**을 구조화하고, **기관 IRB 서식(FORM43) 작성 지침**과 **검증된 PubMed 문헌 근거**를 결합해 연구계획서 **작업 초안(working draft)**을 만드는 시스템을 개발했습니다.
> - 신생아·미숙아 연구 시나리오 100개에서, 로컬 모델(**MedGemma-27B**)과 API 모델(**GPT-6-Luna**) 모두 문헌 보강 후 **관련성(relevance)**이 유의하게 올랐습니다 (+0.208, +0.278점 / 5점 척도).
> - 서식 항목별 완성도는 **참고문헌(4.87–4.93)**과 **연구목적**에서 높고, **연구방법(3.21–3.47)**과 **통계분석(3.40–3.67)**에서 낮았습니다.
> - 연구자가 제공하지 않은 정보는 지어내지 않고 **"추가 정보 필요"로 표시**하도록 설계했습니다.

## 1. 연구 배경 (Introduction)

### 1-1. IRB 연구계획서 작성의 어려움

- IRB 연구계획서를 준비하려면 **구조화된 연구 정보와 문헌 검토**가 필요한데, 이 작업에 시간이 많이 듭니다.
- **외부 생성형 AI 서비스**를 쓰면 개인정보와 데이터 보안 문제가 생깁니다.

### 1-2. LLM 기반 초안 작성의 한계

- LLM이 만든 초안은 **근거 없는 연구 세부사항을 만들어 넣거나**, 제공된 정보를 **빠뜨리거나**, **근거가 부족한 문헌 주장**을 포함할 수 있습니다.
- 따라서 **연구자가 제공한 사실**과 **문헌 근거**를 구분하고, **명시되지 않은 정보는 추가 검토 대상으로 표시**하는 틀이 필요합니다.

### 1-3. 연구 목적

1. **연구자 입력, PubMed 근거, IRB 작성 지침**을 결합한 RAG 기반 틀을 개발합니다.
2. 문헌 보강에 따른 **초안 품질 변화**를 평가하고, 로컬 모델과 API 모델에서 **입력 충실도(input fidelity)**와 **체크리스트 기반 완성도**를 평가합니다.

## 2. 연구 방법 (Methods)

### 2-1. 연구 설계와 데이터셋 구축

- **신생아·미숙아 연구** 관련 PubMed 논문 **100편**을 골라 가상의 연구 시나리오를 만들었습니다.

### Figure 1. 연구 흐름

![Figure 1: Study design and dataset construction](/assets/img/posts/2026-10-23-kosaim-2026/poster-irb-protocol-llm-rag-kosaim-2026-figure-1.png)
*Figure 1: PubMed 원문 연구 → 시나리오 구성 → 연구자 설명 데이터셋 → 초안 생성과 보강 → 세 가지 평가*

```
PubMed 원문 연구 (신생아·미숙아 연구 100편)
        │
        ▼
시나리오 구성 (Methods 기반 각색, GPT-5.6-sol) ── 원문 출처(PMC Methods 문단)는 따로 보관, 생성에는 사용하지 않음
        │
        ▼
Dataset A: 한국어 연구자 설명 (n = 100)
        │
        ▼
IRB 초안 생성과 보강 (MedGemma-27B-text-it 로컬 / GPT-6-Luna API)
   ─ 06A: 구조화된 입력 + FORM43 작성 지침으로 만든 초기 초안
   ─ 06B: 초기 초안을 검증된 PubMed 근거로 보강 (시나리오의 원문 논문은 검색에서 제외)
        │
        ├─▶ 초안 품질: 06A vs 06B, 9개 섹션 (사실성·관련성·유창성·지시 준수, 평가자 Qwen3-32B)
        ├─▶ 입력 충실도: 06B 연구배경 (Projected ROUGE, KLUE-BERT BERTScore)
        └─▶ 체크리스트 완성도: 06B (섹션별 체크리스트, 필수 내용 포함, 인용–참고문헌 대응, 평가자 Qwen3-32B)
```

### 2-2. IRB 초안 생성

- **생성 모델**: MedGemma-27B-text-it (**로컬**), GPT-6-Luna (**API**)
- **입력 구조화**: 연구자의 자유 서술을 구조화된 연구 정보로 바꾸고 서식 항목에 대응시킵니다.
- **초기 초안 (06A)**: 연구자 제공 정보와 서식 작성 지침만으로 생성합니다.
- **RAG 기반 문헌 보강 (06B)**: 관련 PubMed 문헌을 검색·선별·순위화하고, **검증된 근거 문장**으로 초기 초안을 보강합니다. 정보 누설을 막기 위해 **시나리오의 원문 논문은 검색에서 제외**했습니다.

### 2-3. 자동 평가

| 평가 영역 | 평가 기준 | 대상과 기준 | 방법 / 출력 |
| :--- | :--- | :--- | :--- |
| **초안 품질** | 사실성, 관련성, 유창성, 지시 준수 | 06A/06B의 9개 짝 섹션; 연구자 입력과 작성 지침 | Qwen3-32B, 1–5점; 변화 = 06B − 06A |
| **입력 충실도** | 핵심 정보 중복, 의미 유사도 | 06B 연구배경; 연구자 입력 | Projected ROUGE, 약어 정규화한 KLUE-BERT BERTScore; P/R/F1 |
| **체크리스트 완성도** | 필수 내용 포함, 인용–참고문헌 대응 | 06B의 선택 섹션; FORM43 지침 기반 섹션별 체크리스트 | Qwen3-32B, 섹션별 1–5점; 사례 평균 |

### 2-4. 통계 분석

- 초안 품질과 체크리스트 완성도는 **1–5점 척도**로 평가했습니다.
- 초안 품질 점수는 사례 안과 사례 간에 평균했고, 체크리스트 점수는 섹션별로 사례 간 평균했습니다.
- 변화량은 **06B − 06A**로 계산했고, **사례 단위 paired bootstrap 2,000회**로 95% 신뢰구간을 구했습니다.

## 4. 결론 (Conclusion)

1. 문헌 보강은 **로컬 모델과 API 모델 모두에서** 초안의 관련성을 높였고, 개선 폭은 모델과 평가 차원에 따라 달랐습니다.
2. 입력 충실도와 체크리스트 평가는 뚜렷한 강점과 남은 공백을 보여 주었고, 특히 **연구방법**에서 공백이 컸습니다. 합성 시나리오와 자동 평가로 얻은 결과이므로 **실제 사용 전 검증이 필요**합니다.
3. **향후 검증**: 블라인드 전문가 검토와, 수작업 작성 vs 시스템 보조 작성의 **교차 비교(counterbalanced comparison)**를 결합해 사실 정확성, 윤리적 적절성, 실무 유용성, **전문가 검토를 마친 초안까지 걸리는 시간**을 평가할 예정입니다.

### Take-Home Message

> **"Literature enrichment improved IRB draft relevance in both local and API-based models, but research methods remain the largest gap — the system produces a working draft, not a final protocol."**
>
> (문헌 보강은 로컬·API 모델 모두에서 IRB 초안의 관련성을 높였지만, 연구방법은 여전히 가장 큰 공백입니다. 이 시스템이 만드는 것은 최종 계획서가 아니라 **작업 초안**입니다.)

## 포스터 Q&A 및 연구자 노트 (Q&A & Insights)

### 포스터 읽으며 나눈 Q&A (with Claude)

#### Q. 연구 간호사(CRC) 선생님들 업무에 실질적으로 어떤 도움이 될까요?

이 시스템이 겨냥하는 업무는 연구 간호사·연구 코디네이터가 실제로 많은 시간을 쓰는 **IRB 신규 심의 서류 준비**입니다. 포스터 결과를 기준으로 보면 도움이 되는 부분과 아닌 부분이 분명히 나뉩니다.

| 작업 | 기대 효과 | 근거 |
| :--- | :--- | :--- |
| 연구자 메모 → 서식 항목 정리 | **높음** | 입력 충실도 높음 (MedGemma ROUGE-1 Recall 95.46) |
| 연구배경·선행연구 요약, 참고문헌 정리 | **높음** | 참고문헌 4.87–4.93, 연구배경 4.16–4.24 |
| 빠진 정보 확인 (연구자에게 되물을 항목 목록) | **높음** | "추가 정보 필요" 표시 기능 |
| 연구방법, 대상자 선정 근거 | 보통 | 3.21–3.85, 반드시 연구자 검토 필요 |
| 통계분석 계획 | 낮음 | 3.40–3.67, 통계 담당자 작성 필요 |

- 특히 **"추가 정보 필요" 목록**은 그 자체로 쓸모가 큽니다. 연구 책임자에게 무엇을 더 받아야 하는지 체크리스트로 바로 쓸 수 있기 때문입니다.
- 이 시스템은 **로컬 모델로도 작동**하므로, 아직 공개되지 않은 연구 아이디어를 외부 서비스에 보내지 않아도 됩니다.

#### Q. 바로 도입해도 될까요?

아직은 **보조 도구로 시험해 볼 단계**입니다.

1. **실제 IRB 서류가 아닌 합성 시나리오**로 평가했습니다. 실제 연구자의 메모는 더 짧고 불완전합니다.
2. **평가자가 사람이 아닌 LLM(Qwen3-32B)**입니다. LLM 평가자는 유창한 문장에 후한 경향이 있어, 점수가 대부분 4점대로 몰려 있습니다 (천장 효과).
3. **실제 업무 시간 단축이나 IRB 보완 요청 감소는 아직 측정되지 않았습니다.** 저자들도 수작업 vs 시스템 보조 작성의 교차 비교를 향후 과제로 밝혔습니다.
4. **FORM43은 전북대병원 서식**입니다. 다른 기관은 서식과 작성 지침이 달라 그대로 쓸 수 없고, 지침 문서를 바꿔 넣어야 합니다.
5. **책임은 여전히 연구자에게** 있습니다. 근거 문헌의 인용이 실제 내용과 맞는지는 사람이 확인해야 합니다.

#### Q. 통계적으로 잘한 점과 아쉬운 점은?

**잘한 점**
- **같은 사례의 06A와 06B를 비교**하는 paired 설계이고, 사례 단위 bootstrap으로 신뢰구간을 구했습니다.
- 여러 지표를 동시에 검정해 **보정된 p값**을 보고했습니다.
- **정보 누설 방지**: 시나리오의 원문 논문을 검색에서 제외해, 원문을 그대로 베끼는 것으로 점수가 오르지 않게 했습니다.

**아쉬운 점**
- **효과 크기의 임상적 의미**: 5점 척도에서 +0.04–0.28점은 통계적으로 유의해도 실무적으로 체감할 차이인지 불분명합니다.
- **LLM 평가자의 타당도**: Qwen3-32B 점수가 사람 전문가 판단과 얼마나 일치하는지(평가자 간 일치도)가 보고되지 않았습니다.
- **입력 충실도 해석**: ROUGE Recall이 높다는 것은 연구자 입력을 많이 **그대로 옮겼다**는 뜻이기도 합니다. 높을수록 무조건 좋은 지표는 아닙니다.

> 화려한 진단 AI가 아니라 **연구 현장의 행정 부담**을 정면으로 다룬 포스터입니다. "모델이 모르는 것은 지어내지 말고 표시하라"는 설계가 실무적으로 가장 가치 있어 보입니다. 다만 결과가 보여주듯 **연구방법과 통계분석은 AI가 대신 써 줄 수 없는 영역**이고, 이 부분은 오히려 연구 간호사와 통계/AI 연구원이 함께 채워야 할 몫이라는 점도 분명해졌습니다.

### 연구실 적용 아이디어 (Action Items) — 연구 간호사 선생님들과 함께 쓰기

**A. IRB 신규 서류 준비에 "초안 + 빠진 정보 목록" 방식으로 시범 적용** ⭐ 우선순위 1

- 연구 책임자의 연구 아이디어 메모를 받으면, 시스템(또는 원내에서 허용된 로컬 LLM)으로
  1. 기관 서식 항목에 맞춘 **작업 초안**과
  2. **"추가 정보 필요" 목록**을 먼저 만듭니다.
- 연구 간호사 선생님은 이 목록으로 연구자에게 필요한 정보를 한 번에 요청하고, 초안은 반드시 사람이 검토합니다.
- **연구방법과 통계분석 섹션**은 처음부터 통계/AI 연구원이 담당하도록 역할을 나눕니다. 포스터에서 AI가 가장 약했던 영역이기 때문입니다.

**B. 우리 기관 서식으로 바꾸기**

- 이 시스템의 핵심은 **기관 서식 작성 지침(FORM43)**을 프롬프트로 넣는 부분입니다.
- 소속 기관 IRB의 연구계획서 서식과 작성 지침, 그리고 자주 받은 **보완 요청 사례**를 정리해 넣으면 우리 기관에 맞출 수 있습니다.
- 보완 요청 사례 정리는 연구 간호사 선생님들의 경험이 가장 중요한 부분입니다.

**C. 실제 효과를 재는 작은 내부 평가** (통계/AI 연구원 담당)

- 이 포스터가 아직 하지 못한 평가를 우리 연구실에서 작게 해 볼 수 있습니다.
  - 같은 연구를 **수작업 vs 시스템 보조**로 나눠 작성 시간 비교
  - IRB **보완 요청 건수** 비교
  - 연구 간호사 선생님들의 **사용성 평가**
- 이 결과 자체가 실무 개선 근거이자 후속 발표 주제가 될 수 있습니다.

> **추천**: 먼저 **B로 우리 기관 서식과 보완 요청 사례를 정리**하고, **A를 2–3건의 신규 IRB에 시범 적용**해 보는 것이 현실적입니다. 외부 생성형 AI 서비스에 미공개 연구 내용을 넣기 전에 **기관의 AI 사용 지침과 보안 정책**을 먼저 확인해야 합니다.
